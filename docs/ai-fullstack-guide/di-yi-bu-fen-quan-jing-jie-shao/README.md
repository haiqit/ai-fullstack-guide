# 第一部分 · 全景介绍 🗺️

这一部分不写代码，只做一件事：**先把地图画清楚。**

## 为什么先看地图 🧭

AI 全栈最容易踩的坑，不是某个工具不会用，而是不知道该在哪儿用力。

* 有人把 AI 应用当成「前端 + 一次接口调用」，上线第一周就被延迟和成本打醒
* 有人一上来就啃模型原理，却说不清自己的业务请求到底经过哪几层
* 有人工具装了一大堆，换个场景就不知道怎么组合

地图的作用就一个：**新需求进来时，你能立刻判断它落在哪一层、成本项是什么、该谁负责。**

## 本部分内容 📚

**AI 全栈的能力地图**——把一次请求拆成接入、编排、检索、推理、数据与观测五层，逐层说清它在回答什么问题、出问题时长什么样、主要由谁负责。

## 读完你会得到什么 ✅

1. 拿到一个需求，能判断它落在链路的哪一层
2. 知道每一层的典型故障和成本项
3. 明白这套地图怎么对上五个岗位：产品、UI、前端、后端、运维
