# AI 全栈的能力地图

## 从模型到用户

一个 AI 应用上线后收到的每一个请求，大概都会经过下面几层：

```
用户请求
   ↓
接入层      鉴权 / 限流 / 路由 / 降级
   ↓
编排层      提示词组装 / 上下文管理 / 工具调用
   ↓
检索层      召回 / 重排 / 上下文筛选
   ↓
推理层      模型服务 / 批处理 / 缓存
   ↓
数据与观测   向量库 / 日志 / 追踪 / 评测集
```

这五层里，只有推理层是模型自己的领域。**其余四层都是标准的后端工程问题**，这也是后端工程师转向 AI 方向最大的优势所在。

## 每一层在回答什么问题

| 层     | 核心问题                         |
| ----- | ---------------------------- |
| 接入层   | 这个请求该不该进来？该走哪个模型？失败了怎么办？     |
| 编排层   | 这次调用要带什么上下文？要不要调用工具？         |
| 检索层   | 哪些资料和当前问题相关？                 |
| 推理层   | 怎么把请求变成 token，再把 token 变成文本？ |
| 数据与观测 | 出了问题怎么定位？改动的效果怎么衡量？          |

## 一个常见的误判

最常见的误判是：把 AI 应用当成「前端 + 一次 API 调用」。

在这种理解下，团队会跳过编排层和观测层，直接写业务代码。结果一旦上线，马上遇到三类问题：

1. **延迟不可控** —— 没有超时和降级，一次慢请求拖垮整个页面。
2. **成本不可见** —— 不知道钱花在哪，优化时无从下手。
3. **效果无法回归** —— 改了提示词，没人能说清到底变好了还是变坏了。

本书后面的绝大多数内容，本质上都在补这三类漏洞。
