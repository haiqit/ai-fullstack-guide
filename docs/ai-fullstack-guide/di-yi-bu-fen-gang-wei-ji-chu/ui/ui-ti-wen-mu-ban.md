# 提问模板：评审、生成、验收

这些模板用在三个场景：设计评审时问透、让 AI 生成方案、验收 AI 产出。

| 模板        | 什么时候用      | 产出什么        |
| --------- | ---------- | ----------- |
| 🧭 布局方案对比 | 定页面结构      | 三种布局的取舍     |
| 🔄 五态补全   | 设计稿缺态      | 另外四态的设计     |
| 🧱 设计系统选型 | 项目起步       | 现在选哪个、何时换   |
| 🔍 设计稿走查  | 评审前        | 缺口清单        |
| ✅ AI 生成验收 | 拿到 AI 页面   | 不达标项 + 修改方案 |
| 📜 交互模式选型 | 列表 / 分页类需求 | 推荐 + 接口怎么配合 |

## 模板一：布局方案对比 🧭

> 【背景】这是【页面类型】页面，用户是【画像】，从【来源】来，要在【时间 / 步骤】内完成【目标】，主流量在【手机 / 桌面】。 【约束】已有设计系统【有 / 无】，断点【哪些】，不能用【某组件】，信息必须包含【列表】。 【取舍】请给三种布局方案（如单栏 / 双栏 / 卡片网格），分别说明：信息少和信息多时的体验差异、移动端适配成本、实现复杂度、各自的失败条件（什么情况下不好用）。 【验收】每个方案要能回答「主任务是否最显眼、间距是否有刻度、断点怎么切」。

## 模板二：五态补全 🔄（最实用）

> 【背景】这是【功能】的界面，正常态是【描述】。 【约束】后端接口能返回【哪些错误类型】，加载通常【多快】。 【取舍】请补全另外四态：空态（说什么、引导什么）、加载态（骨架屏 / 转圈 / 进度条选哪个）、错误态（怎么提示、能否重试）、边界态（超长 / 无权限 / 已满 / 重复提交各怎么处理）。 【验收】每态要能回答「前端拿到什么数据、显示什么、用户能做什么」。

## 模板三：设计系统选型 🧱

> 【背景】产品是【B 端 / C 端】，团队【人数】，有没有专职设计【有 / 无】，要不要品牌定制或多主题【要 / 不要】。 【约束】技术栈【React / Vue】，不能用【某库】，AI 生成质量要【高】。 【取舍】请对比三种方案（自研 / Tailwind + shadcn / AntD 类），分别说明：适合什么阶段、实现代价、可定制度、AI 生成质量、什么信号出现时该升级。 【验收】给出「现在选哪个 + 什么条件下换」的判断标准，以及 token 方案怎么定。

## 模板四：设计稿走查 🔍

> 这是我的设计稿描述 / 截图：【描述或图】。 请扮演一个要把它实现出来的前端，列出： ① 哪些状态没设计（空 / 加载 / 错误 / 边界）？ ② 哪些间距 / 颜色 / 字号不在刻度上？ ③ 哪些组件可以复用但画了不同样式？ ④ 哪些地方在不同断点下会出问题？ 每条给出「前端要自己补什么、补出来可能和设计不一致的地方」。

## 模板五：AI 生成 UI 的验收 ✅

> 你生成的这个界面，请按以下标准自查并列出不达标处： ① 颜色 / 间距 / 字号是否来自统一 token，有没有写死值？ ② 空态 / 加载态 / 错误态 / 边界态是否都有？ ③ 组件是否拆分复用，有没有重复代码？ ④ 移动端断点下布局是否正常？ ⑤ 可交互元素是否键盘可达、焦点是否可见？ 不达标的，给出修改方案。然后我按这个清单验收。

## 模板六：交互模式选型 📜

> 【背景】列表数据量【量级】，更新频率【高 / 低】，主流量【手机 / 桌面】，用户主要动作是【浏览 / 查找 / 对比】。 【约束】后端分页方式【offset / cursor 可改】，性能预算【多少】。 【取舍】请对比传统分页、无限滚动、加载更多按钮、虚拟列表四种，分别说明：体验差异、后端分页方式要求、实现复杂度、数据变动时的坑（重复 / 漏数据）。 【验收】给出推荐 + 后端接口该怎么配合。
