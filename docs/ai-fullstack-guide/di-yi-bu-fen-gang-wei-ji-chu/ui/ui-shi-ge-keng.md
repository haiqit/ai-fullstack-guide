# UI 岗的十个通用坑

| #  | 坑                 | 一句话后果            |
| -- | ----------------- | ---------------- |
| 1  | 只画有数据的样子          | 空 / 加载 / 错误全靠前端编 |
| 2  | 没有间距刻度            | 每页都像不同人拼的        |
| 3  | 颜色硬编码             | 暗色、换肤全返工         |
| 4  | 同一个东西五种样式         | 改一处漏四处           |
| 5  | 断点拍脑袋             | 平板端崩             |
| 6  | 无障碍缺失             | 部分用户不可用、会被卡      |
| 7  | 动效过度              | 卡顿、首屏变慢          |
| 8  | 表单按数据库字段排         | 填一半跑了            |
| 9  | AI 生成的 UI「看着像不能用」 | 上线没法维护           |
| 10 | 设计稿和代码两套 token    | 永远不同步            |

## 坑一：设计稿只画「有数据」的样子 🖼️

**表现**：设计稿全是列表有数据、表单填好的状态。

**后果**：空态、加载态、错误态、边界态全要前端自己编，编出来和设计不一致。

**怎么防**：把五态当设计交付的硬要求。缺态的设计稿，打回。

## 坑二：没有间距刻度 📏

**表现**：这个页面 13px，那个 17px，下一个 23px。

**后果**：页面之间不协调，后期改间距全量替换，AI 生成时也各写各的。

**怎么防**：定一套间距刻度（4 / 8 / 12 / 16 / 24 / 32…），所有间距只能从刻度里选，写进设计规范。

## 坑三：颜色硬编码 🎨

**表现**：每个组件里写死颜色值。

**后果**：暗色模式、品牌定制、无障碍对比度全要返工。

**怎么防**：token 先行。颜色、字号、圆角、阴影全部变量化。

## 坑四：同一个东西五种样式 🎭

**表现**：按钮在这页圆角 4px，那页 8px；主色有五个近似蓝。

**后果**：产品显得拼凑，维护时改一处漏四处。

**怎么防**：组件库 + 设计系统。同一个语义只允许一种实现。

## 坑五：断点拍脑袋 📱

**表现**：只设计了手机和桌面，平板打开布局错乱。

**后果**：特定设备客诉、返工。

**怎么防**：断点按内容驱动，至少在真机或模拟器过一遍平板和折叠屏。

## 坑六：无障碍缺失 ♿

**表现**：对比度太低、键盘 tab 不到、焦点看不见、图片没 alt。

**后果**：部分用户不可用；某些行业或客户有合规要求，会被卡。

**怎么防**：底线三条——对比度达标（正文 4.5:1）、所有可交互元素键盘可达、焦点态可见。

## 坑七：动效过度 ✨

**表现**：每个元素都在动，页面切换一堆动画。

**后果**：移动端卡顿、首屏变慢、用户烦。

**怎么防**：动效只用在「状态变化需要被感知」的地方，工具型产品能少则少。

## 坑八：表单字段顺序不合理 📝

**表现**：按数据库字段顺序排表单，而不是按用户心智。

**后果**：转化率低，用户填一半跑了，还怪前端。

**怎么防**：字段按用户认知顺序排；能后填的别放前面；必填尽量少；错误提示要具体到字段。

## 坑九：AI 生成的 UI「看着像，不能用」 🤖

**表现**：颜色间距各写各的、只给正常态、组件没拆、类名混乱。

**后果**：上线后发现没法维护、状态缺失、换主题全崩。

**怎么防**：给 AI 生成 UI 定验收标准（模板五），不合格重生成。

## 坑十：设计稿和代码两套 token 🔀

**表现**：设计用一套命名，前端代码用另一套，对不上。

**后果**：改设计要人工同步代码，永远不同步。

**怎么防**：token 单一来源（设计工具导出 → 代码生成），别手工维护两份。

{% hint style="success" icon="lightbulb" %}
十个坑数一数，根子大多是三类：**没刻度、没 token、没五态。** 设计评审时盯这三件事。
{% endhint %}
