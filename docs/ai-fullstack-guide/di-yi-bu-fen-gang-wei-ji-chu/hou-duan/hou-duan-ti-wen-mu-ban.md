# 提问模板：架构、契约、验收

这些模板用在三个场合：技术方案评审、让 AI 设计架构、验收 AI 写出来的后端代码。

| 什么时候用         | 用哪个      |
| ------------- | -------- |
| SaaS 产品要定隔离方案 | 模板一      |
| 有并发场景         | 模板二      |
| 支付回调、消息消费、写接口 | 模板三      |
| 前后端一起定接口      | 模板四（最常用） |
| 要加缓存          | 模板五      |
| 定部署架构         | 模板六      |
| 定监控方案         | 模板七      |
| 验收 AI 写的后端    | 模板八      |

## 模板一：多租户隔离方案

> 【背景】SaaS 产品，客户数【多少】，数据敏感度【高 / 中 / 低】，合规要求【有 / 无】，已有技术栈【描述】。 【约束】不能上【某方案】，运维能力【有 / 无】，成本预算【多少】。 【取舍】请对比三种隔离方案（独立库 / 独立 schema / 共享表 + tenant\_id），分别说明：隔离强度、成本、实现要点、数据泄露风险怎么防、什么信号出现时该升级。 【验收】给出推荐 + RLS / 应用层兜底方案 + 「漏写 tenant\_id」的防呆机制。

## 模板二：并发防冲突方案

> 【背景】表【T】有字段【列表】，存在【并发场景】，冲突频率【高 / 低】，一致性要求【强 / 最终】。 【约束】数据库【Postgres / MySQL】，不能上【分布式锁】，性能预算【多少】。 【取舍】请对比三种方案（唯一索引 / 悲观锁 / 乐观锁），分别说明：正确性、性能、失败重试怎么做、死锁风险、跨服务时怎么办。 【验收】给出推荐 + 数据库约束设计 + 失败处理代码骨架。

## 模板三：幂等设计

> 【背景】这是【支付回调 / 消息消费 / 写接口】，重复来源有【列出】，业务后果【重复发货 / 重复扣款 / …】。 【约束】已有【Redis / DB】，不能用【某方案】。 【取舍】请对比三种幂等方案（幂等键 / 唯一约束 / 状态机校验），分别说明：适合什么、实现要点、存储成本、过期策略、并发下的正确性。 【验收】给出推荐 + 幂等表结构 + 重试和去重的代码骨架。

## 模板四：接口契约设计（前后端一起用）⭐

> 这是我的接口设计：【描述 / OpenAPI】。 请扮演一个要消费它的前端 + 一个要运维它的 SRE，分别列出： ① 错误码能分类吗？前端怎么给不同提示？ ② 分页支持游标吗？无限滚动能用吗？ ③ 返回结构统一吗？ ④ 写操作有幂等吗？重试安全吗？ ⑤ 有健康检查吗？有业务指标吗？日志带 trace\_id 吗？ 每条给出「前端 / 运维要额外做什么、可能出什么事故」。

## 模板五：缓存策略设计

> 【背景】表【T】读多写少比例【多少】，一致性要求【强 / 最终】，QPS【多少】，数据量【多少】。 【约束】已有【Redis】，不能上【某方案】。 【取舍】请对比三种策略（先更新库再删缓存 / 只更新库靠过期 / 多级缓存），分别说明：一致性、性能、实现成本、缓存穿透 / 击穿 / 雪崩怎么防。 【验收】给出推荐 + 缓存 key 设计 + 失效和更新流程 + 兜底方案。

## 模板六：部署架构选型

> 【背景】服务数【多少】，团队【人数】，流量【量级 / 波动】，有无长任务【有 / 无】。 【约束】运维能力【有 / 无】，成本预算【多少】，不能上【K8s / Serverless】。 【取舍】请对比四种架构（单体 / 模块化单体 / 微服务 / Serverless），分别说明：适合什么阶段、运维成本、扩展性、典型坑、什么信号出现时该升级。 【验收】给出推荐 + 部署拓扑 + 运维要做什么（监控 / 扩容 / 回滚）。

## 模板七：可观测性设计

> 【背景】服务【描述】，关键业务指标有【列出】，跨服务【有 / 无】。 【约束】已有【监控系统】，预算【多少】。 【取舍】请设计最小可用的可观测性方案：要埋哪些指标（含业务指标）、日志要带什么字段（trace\_id / 租户 / 用户）、链路要埋哪些点、告警怎么分级。 【验收】给出「后端埋什么、运维接什么」的边界清单 + 故障排查顺序。

## 模板八：AI 生成后端代码的验收

> 你生成的后端代码，请按以下标准自查并列出不达标处： ① 多租户查询有没有带 tenant\_id？有 RLS 兜底吗？ ② 并发场景用了什么防冲突方案？「先查再插」有没有出现？ ③ 写操作幂等吗？支付回调落原始事件了吗？ ④ 错误码分类了吗？返回结构统一吗？ ⑤ 长任务同步执行了吗？该异步化吗？ ⑥ 缓存策略一致吗？有穿透 / 击穿 / 雪崩防护吗？ ⑦ 有健康检查、业务指标、trace\_id 吗？ 不达标的给修改方案。然后我按这个清单验收。

{% hint style="info" %}
模板四和模板八最常用。前者是前后端联调前对一次接口，后者是 AI 写完代码后你能一眼看出哪里会出事。
{% endhint %}
