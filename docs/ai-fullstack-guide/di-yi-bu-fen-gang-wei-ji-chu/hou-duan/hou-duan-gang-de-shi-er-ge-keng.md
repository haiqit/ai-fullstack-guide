# 后端岗的十二个通用坑

每条都说清三件事：什么表现、什么后果、怎么防。

| #  | 坑                   | 一句话          |
| -- | ------------------- | ------------ |
| 一  | 多租户查询漏带 `tenant_id` | 别的租户的数据查出来了  |
| 二  | 防并发只靠「先查再插」         | 两个人同时抢，超卖    |
| 三  | 支付回调不落原始事件、不去重      | 重投就重复发货      |
| 四  | 业务规则只存 ID 不存快照      | 规则一改，历史订单跟着变 |
| 五  | 错误码不分类              | 前端只能给笼统提示    |
| 六  | 接口返回结构不统一           | 前端写一堆适配      |
| 七  | 长任务同步执行             | 请求超时、前端卡死    |
| 八  | 缓存加早了               | 多一个 bug 源    |
| 九  | 没有可观测性              | 线上故障排查靠猜     |
| 十  | 过早拆微服务              | 运维复杂度翻倍      |
| 十一 | 队列消费者不幂等            | 消息重投就重复执行    |
| 十二 | 状态变更不留事件            | 出问题无法追溯      |

## 坑一：多租户查询漏带 `tenant_id` 🏢

**表现**：某个查询忘了加租户条件，返回了其他租户的数据。

**后果**：数据泄露，合规事故。

**怎么防**：RLS 兜底 + ORM 全局过滤 + 测试覆盖 + 代码审查。四道里少一道，迟早出事。

## 坑二：防并发只靠「先查再插」 ⚡

**表现**：先检查「时段是否被占」，然后插入。

**后果**：两个人同时抢，超卖。

**怎么防**：唯一索引 + 捕获异常，或悲观锁 / 乐观锁。记住「先查再插」永远不是方案。

## 坑三：支付回调不落原始事件、不去重 🔁

**表现**：收到回调直接改状态。

**后果**：平台重投就重复发货、重复扣款。

**怎么防**：先落原始事件（带事件 ID）→ 去重 → 再改业务状态。顺序不能换。

## 坑四：业务规则只存 ID 不存快照 📸

**表现**：订单关联「规则 ID」，规则表一改，历史订单跟着变。

**后果**：对账不平、客诉、合规风险。

**怎么防**：涉及钱、合同、合规的，一律存快照或版本号。这条没有商量余地。

## 坑五：错误码不分类 🏷️

**表现**：所有错误都返回 `{code: -1, msg: "失败"}`。

**后果**：前端只能给笼统提示，用户体验崩。

**怎么防**：按业务 / 系统 / 权限 / 校验 / 网络分类，前端按类处理，各类给不同的提示和动作。

## 坑六：接口返回结构不统一 📦

**表现**：有的返回 `{data}`，有的直接返回数组，有的 `{list, total}`。

**后果**：前端要写一堆适配代码。

**怎么防**：统一返回结构 + 统一分页结构。约定一次，后面都省。

## 坑七：长任务同步执行 ⏳

**表现**：导出、报表、发邮件都在请求里同步做完。

**后果**：请求超时、前端卡死、要扩容扛长请求。

**怎么防**：异步化 + 任务状态查询接口。前端才有东西可显示「处理中」。

## 坑八：缓存加早了 🗄️

**表现**：读不多也先加缓存。

**后果**：多一个 bug 源（不一致），多一份运维负担。

**怎么防**：读多写少、一致性容忍度高才加。先优化查询和索引。

## 坑九：没有可观测性 🔭

**表现**：只有日志，没有指标、没有 `trace_id`、没有健康检查。

**后果**：线上故障排查困难，运维不敢扩容。

**怎么防**：三件套 + 业务指标 + 健康检查，按「谁写的代码谁埋」。

## 坑十：过早拆微服务 🧱

**表现**：小团队、三五个服务，上来就 K8s + 微服务。

**后果**：运维复杂度翻倍，分布式问题一堆。

**怎么防**：默认单体或模块化单体。有明确信号（独立扩展 / 部署 / 团队）才拆。

## 坑十一：队列消费者不幂等 📬

**表现**：消息重投，重复执行。

**后果**：重复发货、重复扣款、重复通知。

**怎么防**：消费者一律幂等——幂等键、唯一约束或状态机校验，三种选一种。

## 坑十二：状态变更不留事件 🧩

**表现**：只存当前状态，不存变更历史。

**后果**：出问题无法追溯，审计过不了。

**怎么防**：状态变更留事件日志——谁、何时、从什么状态到什么状态、为什么。

{% hint style="success" %}
十二个坑，根子大多落在三处：**边界没约束（唯一索引 / RLS）、操作不幂等、变更没记录。** 评审时先问这三样，能挡掉一半。
{% endhint %}
