# 前端岗的十二个通用坑

先看总览，再看细节。每条都说清三件事：什么表现、什么后果、怎么防。

| #  | 坑                    | 一句话后果            |
| -- | -------------------- | ---------------- |
| 1  | 服务端状态塞进全局 store      | 缓存不同步，越写越乱       |
| 2  | 手写 fetch + useEffect | 竞态、内存泄漏、重复请求     |
| 3  | 环境变量泄露密钥             | 构建产物公开，密钥泄露      |
| 4  | token 存 localStorage | XSS 一发生，token 被偷 |
| 5  | 无限滚动用 offset 分页      | 重复 / 漏数据         |
| 6  | 错误码不分类               | 只能给笼统提示          |
| 7  | 接口返回结构不统一            | 前端写一堆适配          |
| 8  | SSR 服务没纳入运维          | 挂了整个前端打不开        |
| 9  | 性能凭感觉优化              | 该优化的没动           |
| 10 | 类型不共享                | 接口变更上线才发现        |
| 11 | 测试追求覆盖率              | 主流程一改就崩          |
| 12 | SSR 下用不兼容的库          | 白屏 / 构建失败        |

## 坑一：服务端状态塞进全局 store 🗃️

**表现**：用户列表、详情数据放 Redux / Zustand，手动管理刷新和失效。

**后果**：缓存不同步、bug 多、代码越写越乱。

**怎么防**：服务端数据一律交给请求库（TanStack Query / SWR），全局 store 只放客户端状态。

## 坑二：手写 fetch + useEffect 管请求 🛠️

**表现**：每个页面各写一遍请求逻辑，竞态、取消、重试全靠自己。

**后果**：竞态 bug（后发的请求先回来）、内存泄漏、重复请求。

**怎么防**：用请求库，别自己造轮子。

## 坑三：环境变量泄露密钥 🔑

**表现**：把 API 密钥放进 VITE\_ / NEXT\_PUBLIC\_ 开头的变量。

**后果**：构建产物公开，密钥直接泄露，安全事故。

**怎么防**：前端只放公开配置；密钥一律放后端，前端通过接口间接使用。

## 坑四：token 存 localStorage 🍪

**表现**：为了方便，token 存 localStorage。

**后果**：XSS 一旦发生，token 直接被偷。安全审计过不了。

**怎么防**：优先 httpOnly cookie；必须存 localStorage 时要评估 XSS 风险，并做 CSP。

## 坑五：无限滚动用 offset 分页 📜

**表现**：数据在变动（有新数据插入），offset 分页会重复或漏数据。

**后果**：用户看到重复项、漏项，体验崩。

**怎么防**：无限滚动一律用游标分页（cursor），后端要支持。

## 坑六：错误码不分类，前端只能给笼统提示 🚦

**表现**：后端所有错误都返回 `{code: -1, msg: "失败"}`。

**后果**：前端没法区分「余额不足」和「系统错误」，只能给一个「操作失败」。

**怎么防**：错误码分类（业务 / 系统 / 权限 / 校验 / 网络），前端按类处理。

## 坑七：接口返回结构不统一 📦

**表现**：有的接口返回 `{data}`，有的直接返回数组，有的返回 `{list, total}`。

**后果**：前端要写一堆适配代码，数据请求层没法统一。

**怎么防**：统一返回结构（`{data, error, meta}`），分页统一 `{list, total, cursor}`。

## 坑八：SSR 服务没纳入运维 🖥️

**表现**：以为前端是「静态的」，SSR 服务没监控、没扩容、没回滚。

**后果**：SSR 服务挂了，整个前端打不开，但没人知道。

**怎么防**：SSR 服务按后端标准运维（监控、容量、回滚、日志）。

## 坑九：性能凭感觉优化 📊

**表现**：「感觉慢就优化一下」，没有指标、没有预算。

**后果**：优化了不该优化的，真正慢的没动。

**怎么防**：对着 Core Web Vitals 优化，定性能预算，超了砍功能。

## 坑十：类型不共享，接口变更靠人肉同步 🏷️

**表现**：后端改了字段，前端不知道，上线才发现。

**后果**：线上报错、返工。

**怎么防**：后端定义 OpenAPI / zod，前端生成类型，接口变更编译报错。

## 坑十一：测试追求覆盖率，不测核心路径 🧪

**表现**：单元测试一堆，E2E 一个没有。

**后果**：单测全绿，主流程一改就崩。

**怎么防**：E2E 只测 3–5 条核心路径（登录、支付、主流程），单测测核心逻辑。

## 坑十二：SSR 下用了不兼容的库 💥

**表现**：用了依赖 window / document 的库，SSR 渲染报错。

**后果**：页面白屏或构建失败。

**怎么防**：SSR 项目选库要看兼容性，必要时动态导入（dynamic import）。

{% hint style="success" icon="lightbulb" %}
十二个坑数一数，根子大多落在三处：**状态没分层、接口没契约、安全没兜底**。剩下的是工程默认动作没做——SSR 没运维、性能没指标、测试没主路径、选库没看兼容。
{% endhint %}
