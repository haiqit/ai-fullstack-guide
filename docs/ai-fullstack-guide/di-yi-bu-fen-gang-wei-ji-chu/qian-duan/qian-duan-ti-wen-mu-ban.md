# 提问模板：选型、评审、验收

这些模板用在三个场景：技术方案评审、让 AI 生成方案、验收 AI 产出。

| 模板          | 什么时候用    | 产出什么           |
| ----------- | -------- | -------------- |
| 🧭 框架与渲染选型  | 项目起步     | 推荐 + 部署架构      |
| 🌐 数据请求层设计  | 前端架构定调   | 统一请求层 + 后端要改什么 |
| 🗄️ 状态管理选型  | 状态开始乱    | 每个状态放哪 + 何时上全局 |
| 📜 接口契约评审   | 前后端联调前   | 接口缺口清单         |
| ⚡ 性能优化方案    | 首屏慢      | 按收益排序的优化项      |
| ✅ AI 生成前端验收 | 拿到 AI 代码 | 不达标项 + 修改方案    |

## 模板一：框架与渲染模式选型 🧭

> 【背景】产品是【类型】，主流量在【手机 / 桌面】，要不要 SEO【要 / 不要】，首屏要求【高 / 一般】，有没有重交互【有 / 无】，团队【人数】。 【约束】技术栈【React / Vue】，不能上【某方案】，运维能力【有 / 无】，AI 生成质量要【高】。 【取舍】请对比三种方案（Vite SPA / Next SSR / 静态生成），分别说明：适合什么场景、部署形态、运维成本、首屏和 SEO 表现、什么信号出现时该换。 【验收】给出推荐 + 部署架构 + 运维要做什么（监控 / 扩容 / 回滚）。

## 模板二：数据请求层设计 🌐

> 【背景】项目有【页面数】，其中重交互页面【哪些】，以读为主页面【哪些】，数据更新频率【高 / 低】。 【约束】后端接口返回结构【描述】，错误码【是否分类】，分页【offset / cursor】。 【取舍】请对比两种数据请求方案（RSC 直取 / TanStack Query），分别说明：适合什么页面、缓存和失效怎么设计、错误和重试怎么处理、各自的坑。 【验收】给出统一的数据请求层设计（封装、鉴权、错误归一、缓存策略），以及后端接口要配合改什么。

## 模板三：状态管理选型 🗄️

> 【背景】状态类型有【列表】，哪些跨页面【列】，哪些变化频繁【列】，要不要 URL 保持【要 / 不要】。 【约束】已有【某方案】，不能上【重方案】。 【取舍】请按「作用域从小到大」给方案（本地 / Context / Zustand / Redux / URL），分别说明：适合什么状态、代价、什么时候该升级。 【验收】给出「这个状态该放哪」的判断流程图，以及「什么信号出现时该引入全局 store」。

## 模板四：接口契约评审（前后端一起用）📜

> 这是我的接口设计：【描述 / OpenAPI】。 请扮演一个要消费它的前端，列出： ① 错误码能不能分类？前端怎么给不同提示？ ② 分页方式支不支持无限滚动？ ③ 返回结构统一吗？前端要不要写适配？ ④ 写操作支不支持幂等？重复提交会怎样？ ⑤ 鉴权怎么带？token 过期怎么处理？ 每条给出「前端要写多少额外代码、可能出什么 bug」。

## 模板五：性能优化方案 ⚡

> 【背景】页面【类型】，当前 LCP【多少】、INP【多少】、CLS【多少】，首屏包体积【多大】，主要资源【图片 / 字体 / JS】。 【约束】不能改【某架构】，性能预算【多少】。 【取舍】请按「优化收益 / 成本」排序给方案（图片 / 字体 / 代码分割 / 预加载 / 缓存），分别说明：预期收益、实现成本、可能的风险。 【验收】给出优化后的目标指标 + 怎么测量验证。

## 模板六：AI 生成前端代码的验收 ✅

> 你生成的前端代码，请按以下标准自查并列出不达标处： ① 服务端状态和客户端状态是否分开？服务端数据有没有塞进全局 store？ ② 数据请求有没有竞态、取消、重试处理？ ③ 有没有环境变量泄露密钥？ ④ 错误码有没有分类处理？ ⑤ 有没有写死的样式值（应该用 token）？ ⑥ 空态 / 加载态 / 错误态有没有？ ⑦ 类型是否完整？接口类型从哪来？ 不达标的，给修改方案。然后我按这个清单验收。
