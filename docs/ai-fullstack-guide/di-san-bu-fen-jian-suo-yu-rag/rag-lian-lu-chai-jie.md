# RAG 链路拆解

## 五个步骤

```
切分 → 索引 → 召回 → 重排 → 拼装上下文
```

| 步骤 | 在做什么        | 典型失败模式         |
| -- | ----------- | -------------- |
| 切分 | 把文档拆成可检索的块  | 切断语义、块过大或过小    |
| 索引 | 向量化并写入存储    | 向量模型与查询不对齐     |
| 召回 | 按相似度取 top-k | k 太小漏召回，太大引入噪声 |
| 重排 | 用更贵的模型重排候选  | 直接省掉，导致上下文质量差  |
| 拼装 | 把块塞进提示词     | 超长、重复、顺序混乱     |

## 一个原则

**先保证召回，再优化生成。**

召回不到正确资料，后面提示词写得再漂亮也没用。排查 RAG 问题时，应该先看「正确文档有没有进候选集」，再去看生成环节。

## 常见误区

* 只调 top-k，不看重排质量。
* 用同一套切分策略处理所有文档类型。
* 把检索结果直接拼接，不做去重和顺序整理。
